The maps are made by $repository, an open-source project. Fork it into your own account or organisation to get maps of your repositories.

Set up a fork

  1. Create a token. Create a classic personal access token with only the public_repo scope. Fine-grained tokens don't work, because GitHub refuses them the stargazer list.
  2. Add it as a secret. In your fork, open Settings → Secrets and variables → Actions → New repository secret. Name it STARGAZERS_TOKEN and paste the token.
  3. Enable GitHub Pages. In Settings → Pages, set Source to GitHub Actions.
  4. Enable Actions. Open the Actions tab and enable workflows. GitHub turns off scheduled workflows in forks until you do.
  5. Run it once. Open Actions → Update star maps → Run workflow. After that it runs every Monday.

Why a personal token?

GitHub only lets admins and collaborators of a repository list its stargazers, so the workflow's built-in GITHUB_TOKEN isn't enough. For an organisation that uses SAML single sign-on, also authorise the token for that organisation.

Options

Set these in the env: blocks of .github/workflows/update-maps.yml.

VariableDefaultEffect
INCLUDE_FORKSfalseInclude repositories that are forks
INCLUDE_ARCHIVEDtrueInclude archived repositories
INCLUDE_LOGINSfalseShow stargazers' usernames in map popups and in the published JSON
MAX_GEOCODE800Maximum number of new locations geocoded per run
MAP_LAYERScountries,bubblesLayers shown when a page opens
MIN_STARS0Only list repositories with at least this many stars
LOGOowner's avatarImage file shown in the header instead of the avatar

Run it locally

You need Python 3.10+ and the GitHub CLI, signed in with gh auth login.

pip install git+https://github.com/$repository
stargazer-map fetch --org <owner>   # writes ./data
stargazer-map build                 # writes ./site
python -m http.server -d site
