These maps are rebuilt every week from public GitHub data. Nothing is collected from visitors of this site.

From stars to bubbles

  1. List the repositories of $org: every public repository (by default without forks).$min_stars_note
  2. List their stargazers with the GitHub API, together with the free-text location field of each stargazer's profile.
  3. Geocode each distinct location with OpenStreetMap Nominatim. Locations are normalised first (emoji removed, lowercased), so "Paris 🇫🇷" and "paris" are one lookup. Results are cached, so a location is only looked up once.
  4. Aggregate stargazers by country and by place, and write the result as JSON (see Data files).
  5. Render this static site from that JSON and publish it on GitHub Pages.

What the maps can't tell you

  • Locations are self-reported. Many profiles have none, some are jokes ("Earth", "localhost"), and some are out of date. Only stargazers whose location could be found are on the map.
  • Names can be ambiguous. Nominatim picks the most likely match, so a "Cambridge" can land in England when its owner meant Massachusetts.
  • Stars aren't users. A star is a bookmark or a thank-you. It doesn't mean someone uses the software.
  • Geocoding is rate limited to about one request per second, so a run geocodes a limited number of new locations. Large repositories can take a few weeks to fill in.

Privacy

Only public profile data is used. The published files hold aggregated counts per country and per place. Usernames are left out unless the site owner turns them on.

The map tiles come from Esri and the map library from unpkg, so your browser contacts those servers when a page loads. Your light/dark and layer choices are saved in your browser's local storage and never leave it.
